# 股票取数 Spec 规范

> 本文档定义 BA-quant 项目股票数据采集任务的标准化规范。
> 每次新建取数任务（task{N}-XXX）前，应先在 `specs/` 下准备对应的 spec 文件，作为该任务的"取数契约"。

---

## 1. 为什么需要 Spec

项目内已有 task1/task2/task3 三个取数任务，但每次都是按经验重写脚本，存在以下问题：
- 字段命名不统一（A股用 `close`，港股 westock 用 `last`）
- 涨跌幅计算口径不一致
- 质量校验缺失
- 复盘时难以横向对比不同标的

Spec 文件的作用是 **在写代码前先固化取数规则**，让后续脚本生成、数据校验、图表渲染都有据可依。

---

## 2. Spec 文件结构

一份 spec 文件（YAML 格式）包含以下模块：

| 模块 | 作用 |
|------|------|
| `meta` | 任务元信息（task_id、标的简称、状态） |
| `target` | 标的元信息（名称、市场、代码、行业、币种、涨跌幅限制） |
| `data_source` | 数据源选择与参数（A股/港股差异化） |
| `data_dimensions` | 采集哪些数据维度（K线、公司简况、财务、分红等） |
| `field_mapping` | 字段映射规则（原始字段 → 标准字段） |
| `output` | 输出文件格式、路径、编码、日期格式 |
| `quality_check` | 数据质量校验规则 |
| `deliverables` | 本任务最终交付物清单 |

---

## 3. 使用流程

```
1. 复制 specs/template.yaml → specs/<标的简称>.yaml
2. 填写各字段（参考已有 spec 实例）
3. 在 TASKS.md 登记 task{N}-<简称>
4. 创建 task{N}-<简称>/ 目录，复制 task_template/ 结构
5. 基于 spec 生成取数脚本（scripts/fetch_data.py）
6. 执行取数 → 跑质量校验 → 生成图表
7. 部署到 GitHub Pages
```

## 4. 字段约定（重要）

### 4.1 标准字段名（所有市场统一）

| 标准字段 | 含义 | 单位 |
|---------|------|------|
| `trade_date` | 交易日期 | A股 YYYYMMDD / 港股 YYYY-MM-DD |
| `open` | 开盘价 | 元 / 港元 |
| `close` | 收盘价 | 元 / 港元 |
| `high` | 最高价 | 元 / 港元 |
| `low` | 最低价 | 元 / 港元 |
| `vol` | 成交量 | A股：手 / 港股：股 |
| `amount` | 成交额 | 元 / 港元 |
| `pct_chg` | 涨跌幅 | %，保留 4 位小数 |
| `turnover` | 换手率 | %，保留 2 位小数 |

### 4.2 涨跌幅校验阈值

| 市场 | 板块 | 阈值 |
|------|------|------|
| A股 | 沪市主板 / 深市主板 | ±10% |
| A股 | 科创板（688）/ 创业板（300） | ±20% |
| 港股 | 主板 | ±30%（合理性阈值，非硬限制） |

### 4.3 数据源选择

| 市场 | 主数据源 | 接口 | 备注 |
|------|---------|------|------|
| A股 | 腾讯行情 | `web.ifzq.gtimg.cn/appstock/app/fqkline/get` | 免 token，前复权 qfq |
| 港股 | 腾讯自选股 CLI | `npx westock-data-clawhub@1.0.4` | 输出 Markdown 表格，需解析 |

### 4.4 A+H 双重上市的特殊处理

中芯国际、比亚迪这类 A+H 股，spec 需同时配置两个市场，并额外做：
- A/H 折溢价跟踪：`A股收盘价 / 港股收盘价`（需先按汇率换算）
- 输出文件分 `_a_` / `_hk_` 两套
- 额外生成 `ah_premium.html` 折溢价对比图

### 4.5 分红标的的特殊处理

长江电力这类长期分红标的，spec 额外增加：
- `dividend` 数据维度（除权日、每股分红、分红率、股息率）
- 除权日涨跌幅校验（除权除息效应会导致 pct_chg 显著为负）

---

## 6. Spec 与脚本的关系

Spec 是 **契约**，脚本是 **实现**。基于 spec 生成脚本时应保证：
- 脚本读取 spec YAML（而非硬编码参数）
- 字段映射严格按 `field_mapping` 执行
- 输出路径按 `output.path_pattern` 生成
- 取数完成后自动跑 `quality_check` 列表

未来可考虑写一个 `scripts/spec_runner.py`，输入 spec 路径，自动生成并执行取数脚本。
